# RenderTorch 项目任务书

> 整理日期：2026-11-26
> 项目定位：基于 Python 与 PyTorch 的自定义 3D 编辑器、软件渲染器和教学级物理实验平台。

## 1. 项目目标

围绕三个词设计项目：**快、好用、易维护**。

最终交付分为三个阶段：

1. 完成一个可运行、可扩展的最小闭环。
2. 在闭环上加入刚体、布料和软体模拟，其中布料是重点，提供质点弹簧、PBD、XPBD 三种教学级实现。
3. 将架构、渲染和物理算法整理成部署在 GitHub Pages 上的中文 HTML 讲解书。

项目优先追求：

- 算法清晰、容易阅读和修改；
- 每种物理方法都有独立、可比较的 Demo；
- 核心逻辑不依赖具体 UI；
- 每个阶段都能独立运行和验收；
- 用尽量少的抽象支撑当前需求。

## 2. 已确认的软件架构

### 2.1 总体形式

采用**模块化单体**：一个 Python 项目、一个进程、清晰分层，不引入微服务、复杂插件系统或过度通用的 ECS。

```text
PySide6 界面层
  主窗口 / 属性面板 / 物理控制面板 / 快捷键 / 视口控件
                         ↓
AppController
  场景操作 / 命令分发 / 模拟控制
                         ↓
Scene Core
  场景图 / 对象 ID / 变换 / 网格资源 / 材质 / 选择状态
          ↓                         ↓
PyTorch 计算层                  软件渲染层
矩阵 / 投影 / 物理数值计算       裁剪 / 光栅化 / 深度测试
          ↓                         ↓
                         FrameBuffer
                    RGBA 像素 + 深度 + 物体 ID
                         ↓
                    QImage → Qt 视口
```

### 2.2 模块职责

| 模块 | 主要职责 | 约束 |
|---|---|---|
| `app` | Qt 主窗口、面板、视口控件、输入事件 | 不保存核心业务状态 |
| `core` | 场景对象、对象 ID、变换、网格资源、材质、选择状态 | 不导入 Qt、Pygame 或窗口 API |
| `compute` | PyTorch 矩阵运算、投影、物理数值计算 | 不处理 UI 事件 |
| `renderer` | 软件光栅化、FrameBuffer、深度与 ID 缓冲 | 不管理场景生命周期 |
| `physics` | 刚体、布料、软体与公共模拟数据结构 | 算法之间保持独立 |
| `io` | 后续扩展：项目保存/加载、资源导入 | 本期不实现，不依赖界面控件 |
| `book` | HTML 讲解书源文件与静态资源 | 不混入运行时代码 |

### 2.3 关键技术决策

- 前端使用 **PySide6 / Qt**。
- 最终显示链路使用 **FrameBuffer → QImage → QPainter**。
- **Pygame 不是长期必需依赖**；现有 Pygame 绘制代码可以作为迁移参考。
- 不要求开发者编写 OpenGL，视口继续采用自定义软件渲染。
- PyTorch 用于熟悉的矩阵运算和批量物理数值计算，不默认引入 autograd。
- Scene 是唯一数据源；视口、属性面板和对象列表都读取同一份状态。
- 当前物理参数由 Controller 转换并写入模拟对象；未来对象编辑功能再引入 Command 与撤销重做。
- 父子层级、Command/撤销重做和 `io` 保存加载属于后续编辑能力，本期最小闭环与物理主线不承诺交付。
- 暂不实现完整拾取系统、Gizmo 和编辑器面板，待物理主线完成后再扩展。

## 3. 阶段一：最小闭环

### 3.1 目标

建立一个 Qt 桌面程序，在自定义视口中显示一个 3D 对象，并完成基础相机交互。此阶段验证架构和显示链路，不加入复杂编辑器功能。

### 3.2 任务清单

- [x] 建立 PySide6 主窗口和自定义视口控件。
- [x] 定义不依赖 Qt 的 `Scene`、`SceneObject`、`MeshResource` 基础数据结构。
- [x] 将现有相机与投影数学迁移为独立计算模块。
- [x] 实现基础 FrameBuffer，包括颜色缓冲和深度缓冲。
- [x] 实现三角形裁剪、透视投影和软件光栅化。
- [x] 将 FrameBuffer 转换为 QImage 并显示在 Qt 视口中。
- [x] 支持鼠标轨道旋转、滚轮缩放和窗口尺寸变化。
- [x] 使用一个内置三角形、立方体或现有模型验证完整链路。
- [x] 为核心投影和渲染流程补充自动化测试。

### 3.3 验收标准

- 启动程序后能看到正确的 3D 对象，不再依赖 Pygame 窗口。
- 鼠标旋转和缩放相机时视口实时更新。
- 窗口缩放后图像比例正确。
- 相机默认方向、近远平面和屏幕坐标映射正确。
- 渲染输出没有 NaN、错误面剔除或深度穿插。
- 核心模块可以在不启动 Qt 的情况下进行测试。

## 4. 阶段二：物理扩展

### 4.1 总体目标

在最小闭环上加入三类教学级物理 Demo：

1. 刚体；
2. 布料；
3. 软体。

其中**布料是核心**，必须提供三种可以切换、比较和讲解的实现：

- 质点弹簧模型；
- PBD；
- XPBD。

参考 Matter.js 和 Blender 的算法思想与交互设计，但用 Python 重写清晰的教学实现，不追求完整商业物理引擎。

### 4.2 公共物理基础

先建立三种布料算法共用的数据与时间框架，避免每个 Demo 各写一套：

- [x] 粒子位置、速度、逆质量；
- [x] 固定时间步与子步；
- [x] 重力与基础积分；
- [x] 固定粒子/钉子约束；
- [x] 地面、球体等简单碰撞体；
- [x] 重置、暂停、单步执行；
- [x] 位移、速度、约束误差等基础调试信息。

### 4.3 刚体 Demo

第一版保持简单，不做完整接触求解器：

- [x] 动态球体在重力下运动；
- [x] 静态地面和简单碰撞体；
- [x] 基础速度、冲量和摩擦；
- [x] 球体与布料粒子的碰撞；
- [x] 可暂停、重置和单步观察。

### 4.4 布料 Demo：重点

三种算法使用相同的初始网格、固定条件、碰撞体和显示方式，便于教学比较。

| 方法 | 核心模型 | 教学重点 | 已知特点 |
|---|---|---|---|
| 质点弹簧模型 | 结构、剪切、弯曲弹簧；显式受力积分 | 力、能量、刚度与时间步 | 直观，但较硬时容易不稳定 |
| PBD | 位置投影满足距离约束 | 约束迭代与最终位置修正 | 稳定、易实现，但刚度参数不够物理 |
| XPBD | 带柔度参数的拉格朗日子约束 | compliance、拉格朗日乘子与刚度控制 | 更接近 PBD 的物理化扩展 |

每种算法都需要：

- [x] 独立算法文件；
- [x] 独立参数面板；
- [x] 可重复的初始状态；
- [x] 可视化粒子、约束或线框模式；
- [x] 简单的稳定性/误差指标；
- [x] 对应的单元测试和解释文档。

### 4.5 软体 Demo

使用 XPBD 实现一个可变形立方体或球体：

- [x] 内部和表面粒子；
- [x] 距离约束；
- [x] 简化体积保持约束；
- [x] 与地面和外部球体碰撞；
- [x] 展示受压、回弹和整体变形。

软体部分保持 Demo 级，不扩展为通用有限元或完整连续介质求解器。

### 4.6 物理控制界面

物理阶段只增加一个集中控制面板，提供：

- [x] 模拟类型：刚体 / 布料 / 软体；
- [x] 布料算法：质点弹簧 / PBD / XPBD；
- [x] 开始、暂停、重置、单步；
- [x] 重力、刚度、柔度、迭代次数等基础参数；
- [x] 粒子、线框和实体显示切换；
- [x] 简单性能与稳定性指标。

### 4.7 验收标准

- 三类物理 Demo 都可以在同一个 Qt 程序中运行。
- 三种布料算法使用相同初始条件，并可直接切换比较。
- 默认参数下可以稳定运行，不出现 NaN 或立即爆炸。
- 暂停、重置和单步行为一致。
- 布料可以与地面和基础刚体碰撞。
- 软体能够产生可见、可恢复的形变。
- 数值积分、约束求解和基础碰撞有自动化测试。

## 5. 阶段三：HTML 讲解书

### 5.1 目标

把项目做成一本可在线阅读的中文教学书籍，而不仅是源码仓库。书籍部署在 GitHub Pages，风格参考用户提供的 Hands-On Modern RL 页面：

https://walkinglabs.github.io/hands-on-modern-rl/chapter01_cartpole/metrics

参考重点是信息组织、代码与图示结合、指标展示和交互式讲解，不照搬页面素材。

### 5.2 建议章节

1. 为什么从零搭建一个 3D 与物理教学项目；
2. 总体架构与模块边界；
3. 最小闭环：相机、投影和 FrameBuffer；
4. 软件光栅化与 Qt 图像显示；
5. 物理模拟基础：粒子、时间步和积分；
6. 质点弹簧布料模型；
7. PBD：位置约束与迭代求解；
8. XPBD：柔度与拉格朗日乘子；
9. 三种布料算法的比较；
10. 刚体与软体 Demo；
11. 性能、稳定性与局限性；
12. 后续扩展方向。

### 5.3 每章统一结构

- 直观问题与生活类比；
- 必要公式；
- 算法伪代码；
- 对应 Python 源码链接；
- 图示、动画或交互 Demo；
- 参数与结果指标；
- 常见问题与调试方法。

### 5.4 实现原则

- 使用轻量静态 HTML/CSS/JS，不引入重型前端框架。
- 书籍源码放在 `book/`，构建后通过 GitHub Pages 发布。
- 代码示例尽量与项目中的真实模块对应。
- 图片、动画和公式服务教学内容，不做纯装饰。
- 页面同时适配桌面和移动端阅读。

### 5.5 验收标准

- GitHub Pages 能正常访问书籍首页。
- 三种布料算法都有独立章节、公式、伪代码和真实源码链接。
- 至少包含一个可交互参数示例或可视化对比。
- 页面结构清晰、公式可读、代码可复制。
- 书籍内容与当前代码版本保持一致。

## 6. 建议目录结构

```text
RenderTorch/
├── app/                 # Qt 界面与输入
├── core/                # Scene、选择、对象 ID、变换
├── compute/             # PyTorch 矩阵与投影
├── renderer/            # 软件光栅化与 FrameBuffer
├── physics/
│   ├── common/          # 粒子、碰撞体、时间步
│   ├── rigidbody/       # 简化刚体
│   ├── cloth/           # 质点弹簧、PBD、XPBD
│   └── softbody/        # 简化软体
├── io/                  # 后续扩展：项目与资源导入导出
├── book/                # HTML 讲解书
├── tests/               # 数学、渲染、物理测试
├── resources/           # 内置模型与静态资源
├── main.py
└── docs/
    └── development-roadmap.md
```

现有 `viewing/`、`solid/` 和 `render.py` 按职责逐步迁移，不继续在单个文件中堆叠新功能。

## 8. 测试与维护原则

- 矩阵、投影、裁剪和光栅化优先进行数值测试。
- 物理测试重点验证能量行为、约束误差、时间步稳定性和边界情况。
- 三种布料算法共享测试场景，保证比较公平。
- 核心模块禁止依赖 Qt 事件对象或窗口 API。
- 不在核心逻辑中读取 UI 控件值，由 Controller 负责转换。
- 先保持直接、清晰的实现，只有出现重复和真实需求时才抽象。
- 不在本阶段加入 ECS、插件系统、多进程、GPU 异步或可微渲染。

## 9. 当前明确不做

- 生产级完整物理引擎；
- 高级碰撞检测和完整接触求解；
- 可微渲染与 autograd 物理；
- OpenGL/Vulkan 渲染后端；
- 完整 Blender 风格编辑器；
- 复杂 OBJ 解析器重构；
- 过早的性能优化和通用插件架构。
