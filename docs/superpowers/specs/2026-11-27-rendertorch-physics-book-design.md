# RenderTorch 物理模拟子书设计

- 日期：2026-11-27
- 状态：用户已要求开始实现；本规格固定内容范围、章节结构、交互与验收方式
- 对应图形学子书：`book/` 中已发布的 15 章 3D 内容
- 新增子书目录：`book/physics/`

## 1. 目标

新增一本中文、可交互、可从高中基础知识读起的物理模拟教材。读者应能从一个小球的位置和速度出发，逐步理解力、积分、能量、弹簧、位置约束、碰撞、XPBD、刚体与软体，而不是只记住引擎参数。

教材必须满足：

1. 先讲可观察的现象，再定义符号，再一步推导公式，最后用数值算例和可操作实验验证。
2. 每章细分为编号小节，默认至少 10 个正文小节；关键小节内嵌实验，不把所有实验堆到章末。
3. 每章至少 2 个独立实验，并提供初等直觉、LaTeX 公式、手算算例、伪代码、自测和调试清单。
4. 所有新公式使用 LaTeX，由现有本地 KaTeX 渲染，不依赖 CDN。
5. 真实 Python 实现、浏览器概念实验和后续路线明确分层，不夸大 RenderTorch 当前能力。
6. 继续使用 Python 标准库生成静态 HTML，浏览器端只使用原生 JavaScript、Canvas 2D 与 SVG。
7. 支持 `file://`、本地 HTTP 与 GitHub Pages；实验不请求网络。
8. 保留并突出图形学 15 章，同时让原书大章节增加 `1.1`、`1.2` 式小节编号与章内导航。

## 2. 非目标与边界

- 不重写或扩展 RenderTorch 的 Python 物理引擎，只增加教材和对应数值验证。
- 不引入 WebGL、Three.js、React、Matter.js 运行时或 npm 构建流程。
- 不把浏览器二维实验描述为生产级三维引擎。
- 不复制教材、论文、旧书或商业引擎的正文、图片和实现代码。
- 不修改工作区已有的 `main.py`、`render.py`、`solid/`、`viewing/` 等未提交改动。
- 不在本阶段实现连续碰撞检测、完整接触流形、旋转刚体或有限元求解器；这些只作为概念和后续路线。
- 不清理现有未跟踪文件，不强制推送 Git。

## 3. 读者与教学约定

### 3.1 读者起点

- 会四则运算、基础代数、直角三角形和简单函数图象。
- 不要求先学微积分；速度、加速度、变化率先用“每秒改变多少”解释。
- 会阅读基础 Python/JavaScript 伪代码；实验无需安装依赖。
- 涉及叉积、矩阵、柔度和拉格朗日乘子时，先给几何或“记账”直觉，再给公式。

### 3.2 符号约定

- 二维实验坐标：`x` 向右，`y` 向上；屏幕绘制时单独转换为向下像素坐标。
- 三维概念沿用 RenderTorch 的右手坐标系。
- 位置、速度、加速度、力分别用 `p`、`v`、`a`、`F`。
- 时间步长用 `h` 或 `dt`，质量用 `m`，逆质量用 `w=1/m`；固定点 `w=0`。
- 距离约束误差用 `C`，方向用 `n`，逆质量梯度平方和用 `denom`。
- XPBD 柔度用 `alpha`，有效柔度用 `alpha_tilde`，拉格朗日乘子用 `lambda`。
- 所有展示读数保留有限小数；实验内部计算使用双精度浮点数。

### 3.3 固定教学节奏

每个正文小节采用以下子结构，允许按主题省略非必要项：

1. **生活直觉**：用小球、弹簧、绳子和布料说明问题。
2. **符号与定义**：本章符号集中定义，小节首次出现的量再次说明。
3. **逐步推导**：公式只推进一步，不用“显然”跳过关键代数。
4. **数值算例**：至少一组能手算或代入计算器的数字。
5. **可操作实验**：改变一个参数，观察轨迹、误差、能量或约束图。
6. **伪代码**：短小、可复制、与实验算法一致。
7. **常见误区**：说明错误症状、根因与最小调试动作。
8. **小结**：用两三句话交代本小节与下一小节的关系。

## 4. 网站架构

```text
book/
├── content.py                  # 图形学内容与小节模型
├── physics_content.py          # 物理子书 10 章正文和实验规格
├── build.py                    # 图形学构建器，增加小节编号和物理入口
├── physics_build.py            # 物理子书构建器
├── layout.py                   # 两书共用的页面骨架、转义与页脚
├── assets/
│   ├── physics-core.js         # 可测试的积分、弹簧、PBD、XPBD、碰撞函数
│   ├── physics.js              # Canvas、控件、固定步长与指标公共组件
│   └── demos/physics01.js ... physics20.js
├── index.html                  # 总入口：图形学 + 物理子书
├── chapters/chapter01.html ... chapter15.html
└── physics/
    ├── index.html
    ├── chapters/physics01.html ... physics10.html
    └── references.html
```

物理章节引用 `../assets/...`，与图形学共享 KaTeX、样式和基础脚本。构建器只写自己管理的文件，不递归删除未知内容。

`book/build.py` 继续生成图形学与总入口；`book/physics_build.py` 生成物理子书。发布前依次运行二者，确保一次 `git subtree push --prefix=book origin gh-pages` 包含全部页面。

## 6. 实验契约

每个实验必须提供：

- 明确初始状态与至少一个“重置”按钮。
- 至少两个可操作控件；优先同时提供范围滑块、按钮或可拖拽对象。
- Canvas/SVG 图示和 `aria-live="polite"` 文字读数。
- 当前时间步、误差、能量或接触数等至少一项诊断指标。
- 有限值保护；避免把 `NaN`、`Infinity` 直接展示给读者。
- 固定初始条件，使同一参数得到同一结果。
- 动画尊重 `prefers-reduced-motion`；用户可暂停或单步。
- 控件有对应 `label`，按钮有明确文字，不只依赖颜色区分状态。

`physics-core.js` 暴露纯函数供浏览器和 Node 共用。Node 数值测试验证：积分误差、弹簧稳定性、单次 PBD 投影、逆质量固定点、XPBD 柔度方向、子步不变性、碰撞恢复、摩擦钳制和能量下降。

## 7. 内容与实现状态

每章末尾固定使用：

- **现有 RenderTorch**：只链接真实存在的 `physics/` 与 `app/` 文件。
- **浏览器概念实验**：说明本章 Canvas 实验展示的算法范围。
- **后续实现路线**：列出当前没有的能力，例如角速度、连续碰撞、自碰撞或完整接触流形。

真实源码映射不得指向旧 `book-v2/`、已删除旧书或不存在的文件。浏览器实验的二维可视化不等于 Python 三维实现。

### 7.1 当前实现必须交代的数值边界

- `physics/common/simulation.py` 默认 `fixed_dt=1/120`、`substeps=2`，因此实际积分子步为 \(h=1/240\)；正文必须同时列出这三个量。
- 公共积分器用半隐式 Euler 更新位置，再求解约束，随后根据投影前后位移重建速度；暂停时仍允许单步。
- 当前布料质量弹簧、PBD、XPBD 都是教学级顺序求解；约束误差统一讲最大相对误差。质量弹簧的误差是诊断量，不是位置投影结果。
- 当前地面、静态球和粒子碰撞的摩擦是切向速度乘性衰减，不是完整库仑摩擦；只有球体—粒子耦合使用切向冲量上限。
- 公共 `SphereCollider` 对分离接触的恢复与切向速度计算存在已知问题。新书碰撞算例使用重新推导的正确模型，并明确不把该 Python 路径作为正确冲量范例。
- Python 默认使用 `float32`，浏览器使用双精度；数值实验只要求趋势和容限一致，不要求逐位一致。
- RenderTorch 当前刚体只有平移，没有角速度、转动惯量、力矩、滚动、动态刚体互撞或 CCD。
- 当前软体只有结构/剪切距离约束和六个四面体体积单元；没有面积约束、独立弯曲约束或自碰撞，中心粒子不直接参与体积约束。
- 面积约束、旋转、连续碰撞和自碰撞只能标为浏览器概念实验或后续路线。
