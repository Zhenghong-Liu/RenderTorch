4.2 · 从世界中的一个点到屏幕上的一个位置

相机把三维空间压缩到二维图像

模型坐标描述物体自身，世界坐标描述整个场景，相机坐标描述“从相机看过去”的位置。 把相机放在原点、视线朝向 −z，很多计算会变得简单，因此渲染器先用视图变换把世界点搬到相机空间。

相机空间仍不是屏幕。透视投影让远处的物体看起来更小，把视锥体变成规则裁剪体。 随后除以 w 得到 NDC，再通过视口变换映射到实际像素。整条链路是：

\[\text{world point}\;\longrightarrow\;\text{view point} \;\longrightarrow\;\text{clip point}\;\longrightarrow\;\text{NDC} \;\longrightarrow\;\text{pixel}.\]

图 4.1　每个阶段只做一件事；调试时可以分别检查各阶段坐标。

4.3 · 符号与定义

轨道相机与视锥参数

轨道相机由眼睛位置 E、观察目标 C、世界上方向 U、垂直视场角 f 和宽高比 a 描述。 本章所有方向都先归一化。

\[\begin{aligned} \mathbf f&=\operatorname{normalize}(\mathbf C-\mathbf E) &&\text{（相机前向）},\\ \mathbf r&=\operatorname{normalize}(\mathbf f\times\mathbf U) &&\text{（相机右向）},\\ \mathbf u&=\mathbf r\times\mathbf f &&\text{（相机上向）},\\ a&=\frac{W}{H}. && \end{aligned}\]

当相机恰好与世界上方向共线时，\(\operatorname{cross}(\mathbf f,\mathbf U)\) 会接近零向量。 因此 up 不能任意选取，实际实现应选择不与视线平行的参考方向。

视图矩阵以 \(\mathbf r\)、\(\mathbf u\)、\(-\mathbf f\) 为行，并用相机位置平移。 第三行取负，使相机前方点满足 \(z_v<0\)：

\[V= \begin{pmatrix} \mathbf r^\mathsf T&-\mathbf r\cdot\mathbf E\\ \mathbf u^\mathsf T&-\mathbf u\cdot\mathbf E\\ -\mathbf f^\mathsf T&\mathbf f\cdot\mathbf E\\ 0&1 \end{pmatrix}.\]

于是相机位置变为原点，前向变为 −z。投影矩阵还需要近裁剪距离 n 和远裁剪距离 far：

\[\begin{aligned} P&= \begin{pmatrix} f/a&0&0&0\\ 0&f&0&0\\ 0&0&\dfrac{\mathrm{far}+n}{n-\mathrm{far}}&\dfrac{2\,\mathrm{far}\,n}{n-\mathrm{far}}\\ 0&0&-1&0 \end{pmatrix},\\ f&=\frac{1}{\tan(\mathrm{vertical\_fov}/2)}. && \end{aligned}\]
4.4 · 逐步推导

从裁剪坐标推导 NDC 与像素

设视图空间点为 \((x_v,y_v,z_v)\)，相机看向 −z，因此前方点满足 \(z_v<0\)。投影后：

\[\begin{aligned} x_{\mathrm{clip}}&=(f/a)x_v, & y_{\mathrm{clip}}&=fy_v, \\ z_{\mathrm{clip}}&=\frac{\mathrm{far}+n}{n-\mathrm{far}}z_v +\frac{2\,\mathrm{far}\,n}{n-\mathrm{far}}, & w_{\mathrm{clip}}&=-z_v. \end{aligned}\]

透视除法把裁剪空间变成 NDC：

\[\begin{aligned} x_{\mathrm{ndc}}&=\frac{x_{\mathrm{clip}}}{w_{\mathrm{clip}}},\\ y_{\mathrm{ndc}}&=\frac{y_{\mathrm{clip}}}{w_{\mathrm{clip}}},\\ z_{\mathrm{ndc}}&=\frac{z_{\mathrm{clip}}}{w_{\mathrm{clip}}}. \end{aligned}\]

本章采用 OpenGL 风格 NDC：x、y 位于 [−1,1]，z 位于 [−1,1]。 而图像左上角是 (0,0)，所以视口变换为：

\[\begin{aligned} x_{\mathrm{pixel}}&=\frac{(x_{\mathrm{ndc}}+1)W}{2},\\ y_{\mathrm{pixel}}&=\frac{(1-y_{\mathrm{ndc}})H}{2}. \end{aligned}\]

注意 y 前的负号：NDC 向上，图像 y 向下。 深度 z_ndc 并不随距离线性变化，这就是为什么光栅化需要深度缓冲和透视矫正插值。

4.5 · 数值算例

把一个相机前方点映射到屏幕

取 \(W=512\)、\(H=256\)、垂直 fov=60°， 相机位于 \((0,0,5)\) 并看向原点。此时 \(\mathrm{aspect}=2\)、\(f=1/\tan30^\circ=\sqrt{3}\approx1.732\)。

世界点 \(\mathbf p=(1,0,0)\) 的视图坐标是 \((1,0,-5)\)：

\[\begin{aligned} w_{\mathrm{clip}}&=5,\\ x_{\mathrm{ndc}}&=\frac{(\sqrt{3}/2)\cdot1}{5}\approx0.173205, & y_{\mathrm{ndc}}&=0,\\ x_{\mathrm{pixel}}&=\frac{(0.173205+1)\cdot512}{2}\approx300.34, & y_{\mathrm{pixel}}&=128. \end{aligned}\]

这个点位于画面中心右侧约 44.34 像素处。 若相机后退到 z=10，同一世界点的 x_ndc 约减半，屏幕位置会更靠近中心，这正是透视效果。

近裁剪检查： 位于相机平面上或相机背后的点不能直接做透视除法， 必须先做齐次裁剪，否则 w≤0 会破坏投影。
4.6 · 伪代码与实现映射

按阶段实现投影函数

PYTHON · 列向量管线
def look_at(eye, target, up):
    forward = normalize(target - eye)
    right = normalize(cross(forward, up))
    camera_up = cross(right, forward)
    return rows(
        [*right, -dot(right, eye)],
        [*camera_up, -dot(camera_up, eye)],
        [-forward[0], -forward[1], -forward[2], dot(forward, eye)],
        [0, 0, 0, 1],
    )

def project_to_pixel(point, view, projection, width, height):
    clip = projection @ (view @ [*point, 1.0])
    if clip[3] <= 0:
        return None  # 相机平面或背后，需进入裁剪流程
    ndc = clip[:3] / clip[3]
    x = (ndc[0] + 1) * width / 2
    y = (1 - ndc[1]) * height / 2
    return x, y, ndc[2]

RenderTorch 的 Projection 已包含透视矩阵和屏幕变换矩阵； 相机矩阵由旋转矩阵乘平移矩阵得到。阅读源码时要把本章列向量公式与项目的张量排列逐项对照。

4.7 · 自测

检查视图、投影和视口方向

问题 1：为什么视口变换中 y 前面有负号？

答案：NDC 的 y 向上，图像像素 y 向下，需要翻转。

问题 2：物体远离相机时，投影大小通常怎样变化？

答案：在固定 fov 下，x_ndc 和 y_ndc 的绝对值减小，因此屏幕尺寸变小。

问题 3：相机背后的点为什么不能只做一次透视除法？

答案：其 w_clip≤0，直接除法会得到错误的坐标或符号，必须先裁剪。

4.8 · 常见错误与调试

沿变换链逐段排查

  1. 检查相机位置：视图变换后，眼睛应恰好位于原点。
  2. 检查视线：观察目标应位于相机前方，即视图 z 为负。
  3. 检查 up：不要把世界上方向直接当相机右向；右向由前向与 up 的叉积得到。
  4. 检查宽高比：垂直 fov 固定时，x 投影应除以 aspect，否则画面被拉伸。
  5. 检查像素原点：若内容上下颠倒，优先检查视口 y 符号。
  6. 检查近远平面：单位、交换 n/far 或使用 DirectX 深度范围都会造成错误遮挡。
4.9 · 实现状态

浏览器相机实验与真实源码分层

浏览器概念实验 本章实验用轨道相机参数实时计算 lookAt、 透视投影和像素坐标，并在二维画布中显示世界点与投影位置。它是数学演示，不是完整三维渲染器。
