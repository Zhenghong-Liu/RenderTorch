1.2 · 从屏幕上的小方格开始

图像是有地址的颜色样本

把屏幕放大到足够大，会看到一个由小方格组成的阵列。每个方格叫作一个 像素；计算机不直接保存“红色看起来像什么”，而是保存一组可重复计算的数值。 渲染器的全部工作，最终都要落实到：哪个像素、写入什么颜色、是否更新深度。

本章暂时不讨论三维物体。先假设图像已经是一张表，并建立三个层次的坐标：用于遍历的 整数索引 \((x,y)\)、用于采样的归一化坐标 \((u,v)\)，以及用于数值计算的 通道值。混淆这三者，是图像翻转、越界和颜色错误最常见的根源。

图 1.1　坐标原点位于左上角，x 向右，y 向下；这是图像缓冲区常用的约定。

约定先于公式。 本章采用左上角原点、x 向右、y 向下。 后面相机视口公式会把 OpenGL 风格的左下角 NDC 转换成这套屏幕坐标。
1.3 · 符号与定义

分辨率、坐标和 RGBA

设图像宽度为 W、高度为 H，单位都是像素。 有效像素索引是 \(x\in\{0,\ldots,W-1\}\)、\(y\in\{0,\ldots,H-1\}\)。 因此尺寸为 \(W\times H\) 的图像一共有 \(WH\) 个像素，而不是坐标中的 W+1 或 H+1 个位置。

\[\begin{aligned} u &= \frac{x}{W-1}, & v &= \frac{y}{H-1}, \\ 0 &\le u \le 1, & 0 &\le v \le 1. \end{aligned}\]

u 和 v 把像素中心映射到两端都包含的连续区间。 当纹理真正采样时，也可以采用像素中心约定 \((x+0.5)/W\)；两者解决的是不同问题。 本章使用 \(W-1\)，是为了让第一个和最后一个像素精确落在 0 与 1。

一个彩色像素通常保存红、绿、蓝和透明度四个通道，记作 RGBA。 通道有两种常见表示：

  • 字节表示：整数 0–255，适合帧缓冲区和 PNG 文件；
  • 浮点表示：约 0–1，适合光照、纹理过滤和色调映射。

通道数值描述的是颜色编码或强度，并不自动等同于人眼感受到的亮度。 Gamma 与线性光的关系将在第 14 章展开。

1.4 · 逐步推导

从二维索引到一维内存地址

假设像素按行优先存储，每一行连续排列，RGBA 四个通道也紧密相连。 要找到第 y 行第 x 列，需要先跳过前面的 y 行， 再跳过当前行的 x 个像素。于是：

\[\begin{aligned} \mathrm{pixel\_index} &= yW+x, \\ \mathrm{byte\_offset} &= 4(yW+x). \end{aligned}\]

地址 byte_offset 指向红色通道；随后三个字节依次是绿、蓝、透明度。 如果图像还带有行填充，则每行步长可能大于 4W，这时应使用实际的 stride， 而不能把公式中的 W 当作 stride。

归一化坐标则提供另一种访问方式。给定连续的 (u,v)，在最近邻采样下先取整：

\[x=\operatorname{round}\!\bigl(u(W-1)\bigr),\qquad y=\operatorname{round}\!\bigl(v(H-1)\bigr).\]

取整之后仍要检查范围。边界外的 u,v 可以采用截断、重复边缘像素或镜像重复， 但这些属于纹理寻址策略，不应让它们悄悄造成数组越界。

1.5 · 数值算例

定位 8 × 6 图像中的一个像素

取 W=8、H=6，检查 (x,y)=(5,2)。 它的归一化坐标是：

\[\begin{aligned} u &= \frac{5}{8-1}=\frac{5}{7}\approx 0.714286, \\ v &= \frac{2}{6-1}=\frac{2}{5}=0.4. \end{aligned}\]

该像素之前有 2 个完整行，每行 8 个像素，因此像素索引为：

\[\mathrm{index}=2\cdot8+5=21,\qquad \mathrm{byte\_offset}=21\cdot4=84.\]

也就是说，字节 84–87 存储这个像素的 RGBA。若值为 (12, 200, 64, 255)，转换成浮点通道就是 (0.0471, 0.7843, 0.2510, 1)。透明度 255 表示完全不透明。

手算检查： u 从 0 到 1 时，最近邻索引应从 0 到 7； v 从 0 到 1 时，索引应从 0 到 5。使用 W 而不是 \(W-1\) 会让端点无法到达最后一个像素。
1.6 · 伪代码与实现映射

生成一张可验证的测试图

下面的程序让灰度随 x 增加，并让透明度始终不透明。 它适合作为帧缓冲区、Canvas 上传或图像保存函数的第一个测试。

PYTHON · 概念伪代码
def make_image(width, height):
    image = bytearray(width * height * 4)
    for y in range(height):
        for x in range(width):
            gray = round(255 * x / (width - 1))
            offset = (y * width + x) * 4
            image[offset:offset + 4] = bytes((gray, gray, gray, 255))
    return image

pixel = (5, 2)
offset = (pixel[1] * 8 + pixel[0]) * 4
rgba = tuple(image[offset:offset + 4])

真实项目中，帧缓冲区通常直接分配 NumPy 数组；浏览器实验则用 ImageData.data 写入字节，再用 putImageData 显示。 两种实现的索引公式完全相同。

1.7 · 自测

确认坐标与地址没有脱节

问题 1：4 × 3 图像中，(0,2) 的像素索引是多少？

答案：8。 前面有两行，每行 4 个像素，所以 2×4+0=8。

问题 2：为什么 x 最大只能是 W−1，而不是 W？

答案：索引从 0 开始计数，W 个像素的最后一个索引是 W−1。

问题 3：RGBA=(255,0,0,0) 一定不可见吗？

答案：不透明度和最终合成规则共同决定可见性。Alpha 为 0 通常表示完全透明， 但若混合或保存方式不正确，也可能出现误写；不能只凭一个通道推断最终显示。

1.8 · 常见错误与调试

图像问题的排查顺序

  1. 先检查范围：是否允许 x=W 或 y=H？最后一个有效索引应为 W−1、H−1。
  2. 再检查原点：图像坐标向下，NDC 通常向上；y 翻转常表现为整张图倒置。
  3. 检查通道：RGBA 是否误按 RGB 三个字节步进？透明通道是否始终为 0？
  4. 检查编码：写入 0–1 的浮点到字节数组会接近黑色；写入 0–255 到归一化缓冲区会饱和。
  5. 最后检查 stride：外部图像可能带行对齐，不应假定一行恰好是 4W 字节。

最有效的调试图像是单像素变化、水平灰阶和四角标记。它们能把坐标、寻址和翻转错误直接显示出来。

1.9 · 实现状态

概念实验与当前 RenderTorch 实现

浏览器概念实验 本章实验把图像放大为可点击的像素网格， 允许改变通道值并实时计算归一化坐标与字节地址。它不依赖 WebGL。

现有 RenderTorch renderer/framebuffer.py 已用 numpy.uint8 存储 RGBA 颜色缓冲区， 并用独立数组保存深度和物体编号。该实现与本章的行优先地址模型一致。
