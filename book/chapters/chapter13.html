13.2 · 给三角形贴上图案

UV 是几何与图像之间的坐标契约

网格顶点只有位置还不够。若想让一个表面显示木纹、棋盘或图像， 需要给每个顶点附加纹理坐标 \((u,v)\)。光栅化得到像素的覆盖位置后， 先恢复该像素的 UV，再从纹理中采样颜色。

最容易犯的错误是直接对 UV 做屏幕线性插值。透视投影前后， 屏幕参数与世界距离并不成正比，因此必须复用第 11 章的逆深度方法， 对 \(u/w\)、\(v/w\) 和 \(1/w\) 插值，再相除得到透视矫正 UV。

图 13.1　纹理坐标把二维图案附着到三角形参数域，采样时再恢复每个像素的 UV。

13.3 · 符号与定义

UV、逆深度与采样位置

设三角形三个顶点的纹理坐标为 \((u_i,v_i)\)，裁剪空间齐次坐标为 \((x_i,y_i,z_i,w_i)\)，像素重心坐标为 \(\lambda_i\)。 纹理通常定义在 \([0,1]^2\)，超出范围时由 wrap 或 clamp 策略处理。

定义像素处的逆深度与纹理分子：

\[\frac{1}{w_{\mathrm{pixel}}}=\sum_i\frac{\lambda_i}{w_i},\qquad \widetilde u=\sum_i\lambda_i\frac{u_i}{w_i},\qquad \widetilde v=\sum_i\lambda_i\frac{v_i}{w_i}.\]
\[u_{\mathrm{pixel}}=\frac{\widetilde u}{1/w_{\mathrm{pixel}}},\qquad v_{\mathrm{pixel}}=\frac{\widetilde v}{1/w_{\mathrm{pixel}}}.\]

代码中常写成 u_pixel、v_pixel 与 w_pixel。 它们不是三个独立近似，而是同一透视矫正公式的三个输出。

13.4 · 逐步推导

透视矫正 UV 与纹理过滤

第一步：识别错误插值。 屏幕线性 UV 为 \(u=\sum_i\lambda_i u_i\)、\(v=\sum_i\lambda_i v_i\)。 它只在一个与屏幕平行的表面上正确；一旦三角形前后顶点距离不同，纹理就会滑动或拉伸。

第二步：构造可线性插值的量。 与深度相同， 在屏幕空间线性变化的是 \(1/w\) 与 \(u/w\)、\(v/w\)：

\[u_{\mathrm{pixel}}= \frac{\sum_i\lambda_i(u_i/w_i)}{\sum_i\lambda_i(1/w_i)},\qquad v_{\mathrm{pixel}}= \frac{\sum_i\lambda_i(v_i/w_i)}{\sum_i\lambda_i(1/w_i)}.\]

第三步：映射到纹素。 对 \(W_t\times H_t\) 纹理， 最近邻采样取：

\[i=\operatorname{clamp}(\lfloor uW_t\rfloor,0,W_t-1),\qquad j=\operatorname{clamp}(\lfloor vH_t\rfloor,0,H_t-1).\]

第四步：双线性过滤。 在相邻四个纹素之间按小数部分混合：

\[\mathbf T(u,v)=(1-\alpha)(1-\beta)\mathbf T_{00}+ \alpha(1-\beta)\mathbf T_{10}+(1-\alpha)\beta\mathbf T_{01}+ \alpha\beta\mathbf T_{11}.\]

最近邻保留硬边但会产生锯齿；双线性更平滑，但远景缩小后仍可能摩尔纹。 mipmap 为同一纹理预生成逐级缩小版本，根据屏幕导数选择层级； mipmap 链、三线性过滤和各向异性过滤属于 GPU 纹理管线，本章浏览器实验不实现它们。

13.5 · 数值算例

同一像素的线性和透视 UV

三个顶点的 \(w=(1,2,4)\)，重心坐标 \((\lambda_0,\lambda_1,\lambda_2)=(0.2,0.3,0.5)\)， 纹理坐标为 \((0,0),(1,0),(0,1)\)。

屏幕线性结果为：

\[u_{\mathrm{linear}}=0.3,\qquad v_{\mathrm{linear}}=0.5.\]

透视矫正先求逆深度：

\[\frac{1}{w_{\mathrm{pixel}}}=0.2+\frac{0.3}{2}+\frac{0.5}{4}=0.475.\]

纹理分子为 \(\widetilde u=0.3/2=0.15\)、\(\widetilde v=0.5/4=0.125\)，因此：

\[u_{\mathrm{pixel}}=\frac{0.15}{0.475}\approx0.316,\qquad v_{\mathrm{pixel}}=\frac{0.125}{0.475}\approx0.263.\]

两种结果的差异会直接改变棋盘格采样位置。远端 \(w\) 越大，透视矫正越明显。

13.7 · 自测

坐标、过滤与远景

问题 1：什么时候屏幕线性 UV 恰好正确？

答案：三个顶点的 w 相同，或三角形所在平面与屏幕平行时。

问题 2：为什么不能先算 w_pixel，再直接用它修正 UV？

答案：必须保留三个顶点各自的 1/w_i 加权；单个像素深度不能替代顶点信息。

问题 3：双线性过滤能完全消除远景摩尔纹吗？

答案：不能。缩小时一个纹素可能覆盖多个像素，需要 mipmap 或更完整的过滤策略。

问题 4：UV 超出 [0,1] 时必须报错吗？

答案：不一定。可以由纹理的 wrap/clamp 策略决定重复、镜像或延伸边缘。

13.8 · 常见错误与调试

纹理滑动、翻转与锯齿

  1. 相机移动时纹理滑动：检查是否使用透视矫正 UV。
  2. 图像上下颠倒：统一图像原点与 UV 的 v 方向；很多图像文件从顶部开始，而参数曲面从底部开始。
  3. 接缝闪烁：检查共享顶点是否具有一致 UV，wrap 模式是否统一。
  4. 最近邻出现锯齿：可切到双线性；远景仍闪烁时考虑 mipmap。
  5. 边缘拉出条纹：采样前按约定 clamp 或 wrap，并检查纹素坐标是否少加/多加 0.5。

先用纯色 UV 渐变代替真实纹理，再验证坐标连续性，最后加入棋盘与双线性过滤。

13.9 · 实现状态

当前网格与纹理实现

浏览器概念实验 本章用程序棋盘纹理对比屏幕线性 UV 与透视矫正 UV， 支持 nearest/bilinear 过滤和远端深度调节。

现有 RenderTorch core/primitives.py 只生成位置与面索引； solid/custom.py 不解析 OBJ 的 UV/法线；renderer/rasterizer.py 只对深度做 \(1/w\) 插值，没有通用顶点属性缓冲。

后续实现路线 增加顶点 UV → 透视矫正属性插值 → 最近邻/双线性采样 → wrap/clamp → mipmap。完整 GPU 纹理链不在当前浏览器实验中实现。
