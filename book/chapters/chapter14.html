14.2 · 阴影与显示变换

一个判断可见性，一个决定如何上屏

阴影不是把表面整体调暗，而是询问：从当前表面点走向光源的路径上，是否有更近的物体？ shadow mapping 把这个问题转换成两次渲染：先从光源视角记录最近深度，再从相机视角比较深度。

着色器计算出的颜色通常在线性空间，可能大于 1，也不等于人眼感知的显示亮度。 上屏前需要控制高光不过曝，并做 gamma 显示变换。阴影与显示变换属于两个独立问题， 本章分别推导，最后组合成完整输出。

14.3 · 符号与定义

光源深度、bias 与线性颜色

设光源相机为观察者，\(d_{\mathrm{map}}(u_s,v_s)\) 是 shadow map 中记录的最小光空间距离， \(d_{\mathrm{frag}}\) 是当前表面点的光空间距离。两者必须使用同一投影、同一坐标约定和同一单位。

深度偏移 \(b\ge0\) 用来抵消浮点误差与离散阴影图的深度量化。 设阴影可见因子 \(\xi\in[0,1]\)，\(\xi=1\) 表示受光，\(\xi=0\) 表示完全遮挡。

设曝光为 \(E\)，色调映射函数为 \(T\)，gamma 近似指数为 \(\gamma=2.2\)。 线性颜色可以超过 1，显示颜色必须最终落在 \([0,1]\)。

14.4 · 逐步推导

shadow mapping、Reinhard 与 gamma

第一步：光源深度Pass。 把相机放在光源处， 渲染场景深度但不写颜色。每个阴影图像素保留最近物体距离：

\[d_{\mathrm{map}}=\min_{\text{覆盖样本}} d_{\mathrm{light}}.\]

第二步：相机颜色Pass。 把当前表面点变换到同一光源空间， 采样 shadow map 并比较：

\[\xi= \begin{cases} 1,&d_{\mathrm{frag}}\le d_{\mathrm{map}}+b,\\ 0,&d_{\mathrm{frag}}>d_{\mathrm{map}}+b. \end{cases}\]

bias 太小会产生 shadow acne（表面自己遮挡自己）；太大则产生 peter panning（阴影与物体脱离）。 实际系统还常用斜率相关 bias 和 PCF 多样本平均。

第三步：应用曝光与 Reinhard。 曝光先把场景亮度缩放到可观察范围， Reinhard 将无限正数单调压缩到 \([0,1)\)：

\[\mathbf C_{\mathrm{exposed}}=E\mathbf C_{\mathrm{linear}},\qquad \mathbf C_{\mathrm{reinhard}}=\frac{\mathbf C_{\mathrm{exposed}}}{1+\mathbf C_{\mathrm{exposed}}}.\]

第四步：gamma 显示变换。 近似显示编码为：

\[\mathbf C_{\mathrm{display}}\approx \operatorname{clamp}(\mathbf C_{\mathrm{reinhard}}^{1/2.2},0,1).\]

代码中可写成 C_linear^(1/2.2) 与 C_reinhard。 必须先色调映射再 gamma；顺序交换会改变高光滚动与中间调亮度。 gamma 2.2 是教学近似，严格 sRGB 使用分段传递函数。

14.5 · 数值算例

高光压缩与阴影比较

某像素未遮挡时线性颜色为 \((0.5,0.5,0.5)\)，被遮挡后 Direct 项乘以 \(\xi=0\)。 若仍有环境光 \((0.1,0.1,0.1)\)，两像素会分别保留受光与阴影差异。

取线性值 \(C=2\)，曝光 \(E=1\)。直接 gamma 会得到 \(2^{1/2.2}\approx1.366\)，随后被 clamp 成纯白； 先 Reinhard 则得到：

\[\mathbf C_{\mathrm{reinhard}}=\frac{2}{1+2}=\frac23,\qquad \mathbf C_{\mathrm{display}}\approx\left(\frac23\right)^{1/2.2}\approx0.821.\]

这样高于 1 的高光仍保留亮度层次，而不是全部截断为白色。

阴影比较例：\(d_{\mathrm{map}}=4.0\)、\(d_{\mathrm{frag}}=4.02\)、\(b=0.01\)。 因为 \(4.02>4.01\)，该样本被遮挡；把 bias 调到 0.03 后变为受光，可清楚观察 bias 的作用。

14.6 · 伪代码与源码映射

阴影可见性与显示输出

JAVASCRIPT · 概念伪代码
const lightDepth = sampleShadowMap(lightUv);
const visible = fragDepth <= lightDepth + bias ? 1 : 0;
const litLinear = ambient + direct * visible;
const exposed = litLinear * exposure;
const reinhard = exposed / (1 + exposed);
const display = reinhard.map((channel) => Math.pow(Math.max(0, channel), 1 / 2.2));
framebuffer.color[pixel] = clamp(display, 0, 1);

RenderTorch 的 FrameBuffer 只有一份颜色、一份相机深度和物体编号， 没有光源深度 Pass，也没有在线性 HDR 缓冲上执行色调映射。

14.7 · 自测

深度比较与输出顺序

问题 1：为什么 shadow map 不能直接用相机深度缓冲？

答案：阴影需要从光源视角记录遮挡关系，相机视角无法回答“光源是否看得见该点”。

问题 2：bias 过小和过大分别有什么症状？

答案：过小出现 shadow acne；过大出现阴影脱离物体的 peter panning。

问题 3：Reinhard 的作用是什么？

答案：把无上界的线性 HDR 颜色平滑压缩到有限显示范围，同时保留高光层次。

问题 4：应该先 gamma 还是先 Reinhard？

答案：先在线性空间曝光和色调映射，最后做 gamma 显示编码。

14.8 · 常见错误与调试

自阴影、漏光与灰蒙蒙

  1. 表面全是条纹：检查 shadow map 分辨率、斜率 bias 和光源空间变换。
  2. 阴影悬空：bias 或法线偏移过大。
  3. 移动光源时阴影不动：检查光源视图矩阵与 shadow map 是否同步更新。
  4. 高光全白：在线性 HDR 中保留大于 1 的值，先 Reinhard 再 gamma。
  5. 中间调太暗：检查是否在线性空间提前 clamp，或遗漏 gamma 显示变换。

调试阴影时先把所有材质设为无高光纯色，再检查 PCF，最后恢复光照细节。

14.9 · 实现状态

当前阴影与颜色管理状态

浏览器概念实验 本章在 CPU 上生成小型 shadow map， 用 depth bias 比较方块与球的遮挡，并显示线性、Reinhard 和 gamma 后颜色。

现有 RenderTorch renderer/framebuffer.py 直接保存 8 位 RGBA 与相机深度；renderer/pipeline.py 每帧只做相机投影和逐面着色。 当前没有 shadow map、HDR 颜色缓冲、曝光、色调映射或 gamma 输出。

后续实现路线 光源视图矩阵 → 光源深度 Pass → bias/PCF → 线性 HDR framebuffer → 曝光与 Reinhard → gamma/sRGB 编码。
